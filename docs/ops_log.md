# 연구 수행 일지 (Ops Log) — 환경·장애·우회 기록

분석 **내용**이 아니라 분석을 **수행하는 과정**의 기록: 어떤 환경 제약에
막혔고, 원인을 어떻게 진단했고, 무엇으로 우회했는가. 최종보고서의 "연구
수행 과정" 서술과, 같은 환경(기관망 PC)에서 재현하려는 후속 연구자를 위한
문서다. 분석 방법의 정본은 `methods.md`, 이 문서는 그 방법이 **돌아가게
만든 과정**이 정본이다.

- 기록 틀: **막힘 → 원인 진단 → 대처 → 교훈**. 수행상 장애·우회가 생길
  때마다 날짜별로 추가한다. [규칙 2026-10-16]

## 1. [2026-10-13~15] 위성영상 반입 — 다운로드 관리의 함정들

- **막힘 ①**: 다운로드가 밤새 멈춘 듯 보임(9/20장, 쓰는 중 파일 0개).
  → **진단**: 포털이 권역(은평) 배치를 순차 전송하는 중이었음 — 다음날 재개
  확인. **교훈**: "멈춤"과 "배치 대기"는 파일 수정시각만으로 구분 안 됨,
  하루 단위로 재점검.
- **막힘 ②**: 보령 7장의 Aux.xml 미수령 — 국토위성 tif는 내부 지오태그가
  전혀 없어 Aux가 georeference의 유일한 전거인데, 그게 빠짐.
  → **대처**: 장면 ID 목록(파일명 규칙 `C1_일시_궤도_장면번호` 해설 포함)을
  만들어 사용자에게 전달, 포털에서 메타데이터만 재다운로드.
  **교훈**: 위성영상 반입 검증에 "밴드 tif 존재"만이 아니라 "georeference
  전거 존재"를 포함해야 함 → validate_layers의 raster_scene_set 검사에 반영.
- **막힘 ③**: 신청 목록과 도착 장면 불일치(목록외 3장, 0바이트 잔해 1장).
  → **대처**: 전수 대조 스크립트로 분류(대체 주문 2장은 사용자 확인으로
  확정, 잔해는 정리 대상). **교훈**: 수동 다운로드 자료는 "신청 대비 도착"
  전수 대조를 기본 절차로.

## 2. [2026-10-15] Georeference — 지오태그 없는 위성 tif

- **막힘**: tif에 좌표 정보가 없고(GeoTIFF 태그 부재), Aux 모서리는 "기울어진
  자료 사각형"의 네 귀퉁이라 그대로는 래스터 격자에 못 붙임. GDAL이 없어
  기성 도구도 불가.
- **대처**: ① 변 길이 비교로 "북향 격자 + 기울어진 자료영역 + 검은 여백"
  구조임을 판정 ② 여백을 스캔해 자료 사각형의 네 극점 픽셀을 찾고 Aux
  모서리와 짝지어 아핀 최소제곱 적합(순수 파이썬, 행 스트립 임의 접근)
  ③ RMS 잔차를 품질 게이트(50m)로.
- **파생 장애 2건**: 흩어진 밝은 픽셀(노이즈)에 극점 탐지가 속음 → 연속
  런(50px/60px) 기준으로 견고화. 은평 1장은 Aux 자체가 래스터와 82m 불일치
  (제품 품질 문제) → 커버리지 기여 0 확인 후 분석 셋에서 제외.
- **교훈**: 메타데이터(Aux)도 데이터처럼 검증 대상이다. 적합 잔차를 남겨야
  "어느 장면을 못 믿는지"가 수치로 드러난다.

## 3. [2026-10-16] GPU 추론 외부화 — 기관망 보안정책과의 싸움

GeoAI 탐지(Grounding DINO)는 GPU가 필요한데 기관 PC에 GPU가 없음 → 무료
GPU(Colab)로 추론만 외부화하는 설계. 여기서 보안정책 장애가 연쇄 발생.

- **막힘 ①**: 당초 설계(Google Drive로 타일 4.9GB 전달)가 **Drive 차단**으로
  불가. 사용자가 Drive 접속 자체가 안 됨을 보고.
  → **진단**: 로컬에서 curl로 후보 서비스 전수 프로브 —
  `drive.google.com → 503(차단)`, `colab/kaggle/huggingface/pypi → 200(개방)`.
  브라우저 증상만으로 추측하지 않고 **차단면을 네트워크 레벨에서 실측**.
  → **대처**: 전송로를 **HuggingFace 비공개 데이터셋**으로 교체
  (`s3_hf_transfer.py`): 로컬→HF 업로드(장면별 zip), Colab이 토큰으로 반입,
  결과 CSV도 HF로 반출, 로컬이 회수. 토큰은 .env(비커밋).
- **막힘 ②**: Colab 홈 화면이 GapiError로 깨짐 — Colab의 노트북 열기/저장이
  내부적으로 Drive API에 의존하기 때문.
  → **진단**: googleapis 계열 엔드포인트는 개방(정상 응답) → 실행 환경은
  살아 있고 "Drive를 경유하는 진입로"만 죽은 것으로 판정.
  → **대처**: 노트북을 GitHub 공개 저장소에 푸시하고
  `colab.research.google.com/github/<repo>/...` 직접 진입 URL로 우회. 저장
  불가(Drive 필요)는 감수 — 세션 내 값 입력만으로 돌도록 노트북을 설계.
  플랜 B로 Kaggle(개방 확인) 겸용이 되게 노트북을 플랫폼 중립화.
- **막힘 ③**: 실행 중 `post_process_grounded_object_detection()`의 인자명이
  transformers 신버전에서 변경(box_threshold→threshold)되어 TypeError.
  → **대처**: Colab 쪽은 즉석 수정, GitHub 원본도 수정·푸시 — 세션이 끊겨
  노트북을 다시 열어도 같은 에러가 재발하지 않게.
- **보안 설계 (의도된 비대칭)**: 클라우드로 나가는 것은 **영상 타일뿐**
  (비공개 데이터셋 강제 — 영상 라이선스상 재배포 금지라 private 아니면
  업로드 스크립트가 중단). 전력설비 **좌표**(OSM 대조 기준, out/internal)는
  어떤 클라우드에도 올리지 않고, 탐지 결과와의 대조는 전부 로컬에서 수행.
- **복원력 설계**: 무료 GPU 세션은 예고 없이 끊기므로 ① 50타일마다 결과
  CSV 플러시 ② 재실행 시 완료 타일 건너뛰기 ③ 결과를 HF에 중간 백업 —
  "전체 재실행 = 이어하기"가 되도록.
- **막힘 ④ (사고)**: 1차 전체 실행(17,414타일, 약 2.4시간)이 완료됐으나,
  사용자가 자리를 비운 사이 **반출 셀(셀 7) 실행 전에 Colab VM이 교체**되어
  /content의 결과 파일이 통째로 유실. 로컬 플러시 체크포인트는 VM과 함께
  사라지므로 "마지막 반출 전 세션 소멸"을 못 막았다 — 설계 공백.
  → **대처**: 탐지 루프가 1,000타일마다 중간 결과를 HF에 자동 백업하도록
  수정(hf_backup). 셀 3의 HF 복원과 맞물려, VM이 교체돼도 끊긴 지점부터
  이어 돈다. **교훈**: 휘발성 실행 환경에서 체크포인트는 반드시 **실행
  환경 밖**(원격 저장소)에 둬야 한다. 로컬 디스크 플러시는 커널 재시작만
  막아줄 뿐 VM 교체에는 무력하다.
- **교훈**: ① 기관망에서 클라우드 작업은 "무엇이 막혔는가"를 추측하지 말고
  엔드포인트별로 실측하라 ② 차단된 서비스(Drive)와 그 서비스에 **의존하는
  기능**(Colab 홈/저장)은 별개로 죽는다 — 의존성을 끊는 진입로(GitHub)와
  전송로(HF)를 따로 설계하면 산다 ③ 외부 실행물은 반드시 원본(저장소)과
  동기화해 세션 소멸에 대비.

- **폴더 개편**: 사용자가 `정사영상_전국/위성정사영상_분석대상지역`을
  `정사영상_전국/위성정사영상_분석대상지역`으로 개명(추가 지역 장면 수용 전제).
  layers.yml path만 갱신, validate_layers OK 89. 타일(`tiles_pilot`)·전송 스크립트는

## 5. [2026-10-26] 제로샷 탐지 완주 — 무료 GPU 분할 실행의 교훈

- **막힘**: 52,369타일 추론(약 7시간)을 무료 GPU로 돌리는데 ① Colab GPU
  한도가 며칠째 찔끔 배정·세션 조기 종료 ② 사용자 PC 야간 자동 종료.
- **대처**: ① HF 중간 백업 주기 1,000→200타일로 단축(끊겨도 ~1.5분만 손실)
  ② 처리완료 목록(processed_tiles.txt)으로 탐지 0건 타일도 재개 대상에서
  제외(화성 농지처럼 0건 타일이 많은 구간에서 재탕 방지) ③ Colab 무료 한도가
  막히자 Kaggle(주 30h·단일 세션 9h 보장)로 전환 — 같은 노트북·같은 HF 재개
  로직으로 플랫폼만 교체, 끝까지 완주.
- **함정 기록**: (a) GitHub에서 노트북을 고쳐도, 사용자가 열어둔 기존 탭은
  옛 버전이라 수정이 반영 안 됨 — '탭 닫고 GitHub 링크로 새로 열기' 필요.
  (b) Kaggle은 Accelerator(GPU)와 Internet을 각각 켜야 하고 둘 다 휴대폰 인증
  요구. Internet OFF면 pip·HF가 NameResolutionError. (c) "GPU 없이 연결"은
  CPU 실행이라 20배 느림 — 함정 버튼.
- **교훈**: 장시간 추론은 휘발성 무료 GPU 여러 조각으로 나뉠 것을 전제로,
  체크포인트를 (i) 실행환경 밖 저장소에 (ii) 촘촘히 (iii) 처리완료 전수 기록으로
  둔다. 플랫폼 독립(Colab/Kaggle 겸용)이 한도 리스크의 보험이다.
